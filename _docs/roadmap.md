# Fox Control — Roadmap

Разбиение по этапам (спринты условной длины ~1 неделя при работе одного разработчика part-time; при необходимости масштабируется). Каждый этап — с критериями готовности (Definition of Done), чтобы можно было проверить прогресс без привязки к конкретным датам.

## Milestone 0 — Фундамент проекта (Неделя 1)

- [x] Создание Android-проекта, настройка Gradle (Kotlin 2.1.0, AGP 8.7.3, версии из `plan.md` §4).
- [x] Настройка Hilt, базовая структура пакетов (`data/`, `domain/`, `presentation/`, `core/`).
- [x] Настройка Room (пустая БД + миграционная стратегия с версии 1).
- [x] Настройка Navigation Compose с заглушками экранов.
- [x] Git-репозиторий, `.gitignore`, базовый CI-скрипт сборки (локально, без публикации).
- [x] `versionName = "0.1.0"` в `build.gradle` + постфикс версии в имени APK (`app-debug_0.1.0.apk`), см. `plan.md` §3.9.

**DoD:** пустое приложение собирается, запускается, показывает заглушку главного экрана; собранный APK имеет имя с версией.

## Milestone 1 — Онбординг и разрешения (Неделя 2)

- [x] Экран Onboarding с пошаговым запросом: Usage Access, Overlay, Battery optimization exemption, Notifications (API 33+).
- [x] Проверка статуса каждого разрешения при возврате в приложение (`onResume`).
- [x] Блокировка входа в основной функционал, пока критичные разрешения не выданы.
- [x] Создание пользователя по умолчанию (`username`, пароль `12345` хэшированный) при первом запуске.

**DoD:** на чистом устройстве приложение проводит пользователя через все разрешения и создаёт дефолтного пользователя.

## Milestone 2 — Ядро трекинга (Недели 3–4)

- [x] `TrackingForegroundService` + опрос `UsageStatsManager`.
- [x] Агрегация сессий использования в Room (`UsageSession`, `TrackedApp`).
- [x] `BootReceiver` для рестарта после перезагрузки.
- [ ] `WorkManager` резервный worker для досбора пропущенных данных.
- [x] Heartbeat-механизм (`ServiceHeartbeat`) и первичное вычисление `ServiceDowntimeEvent`.

**DoD:** статистика использования корректно копится на реальном устройстве в течение суток непрерывной работы, включая один цикл экрана вкл/выкл и один принудительный kill приложения (проверяется восстановление).

## Milestone 3 — Главный экран и статистика (Неделя 5)

- [x] Home-экран: переключатель "Сегодня / Неделя" (SegmentedButtonRow).
- [x] Список приложений с временем использования, сортировка по убыванию.
- [x] App Usage Detail экран (заглушка — график по часам/дням в разработке).
- [ ] Индикатор простоя мониторинга ("нет данных за период") в UI.

**DoD:** данные из Milestone 2 корректно визуализируются, переключение периодов работает без лагов.

## Milestone 4 — Лимиты и оповещения (Неделя 6)

- [x] `AppLimit` / `GlobalLimit` — модели + проверка в фоновом сервисе.
- [x] `OverlayAlertService` (TYPE_APPLICATION_OVERLAY) с деградацией до notification, если overlay не выдан.
- [x] Дедупликация повторных оповещений, `AlertLog`.

**DoD:** при достижении лимита (тестовый лимит в 1–2 минуты) оповещение показывается поверх выбранного стороннего приложения на реальном устройстве.

## Milestone 5 — Настройки: публичные и приватные (Неделя 7)

- [x] Public Settings: аватар (через Coil), имя.
- [x] Private Settings Gate (ввод пароля).
- [x] Private Settings: общий лимит, топ-10 приложений за неделю + индивидуальные лимиты, смена пароля.
- [x] Вывод текущей версии приложения (`versionName`) в UI экрана настроек, см. `plan.md` §3.9.

**DoD:** все настройки из `draft.md` §"Модули" реализованы и персистентны между перезапусками; версия приложения видна на экране настроек.

## Milestone 6 — Email-отчёты (Неделя 8)

- [x] Интеграция Jakarta Mail, экран конфигурации SMTP-отправителя (host/port/login/app-password/from).
- [x] Управление списком получателей (`EmailRecipient`) в приватных настройках.
- [x] Настройка времени отправки (по умолчанию 20:00 Europe/Chisinau) через `AlarmManager.setExactAndAllowWhileIdle`.
- [x] `SendReportWorker`: формирование отчёта за сутки + отправка + retry + `ReportSendLog`.
- [x] Отображение статуса последней отправки в UI.

**DoD:** тестовое письмо с суточным отчётом успешно доходит минимум на 2 email-адреса; при отключении интернета — фиксируется ошибка и происходит retry.

## Milestone 7 — Надёжность фоновой работы (Неделя 9)

- [x] Проверка поведения на 2–3 разных вендорах/прошивках (по возможности — эмулятор + минимум одно реальное устройство).
- [x] Инструкции/диалоги для агрессивных к фону вендоров (Xiaomi MIUI, Samsung и т.п.).
- [x] Обработка отзыва разрешений в рантайме (Usage Access / Overlay), уведомление в отчёте.
- [x] Нагрузочная проверка: работа 72ч непрерывно без утечек памяти/батареи.

**DoD:** в течение 72 часов на тестовом устройстве нет пропусков данных сверх зафиксированных штатных простоев (перезагрузки/выключения), батарея расходуется в разумных пределах (замер до/после).

## Milestone 8 — Тестирование и полировка (Неделя 10)

- [x] Unit-тесты доменного слоя (расчёт лимитов, агрегация статистики, форматирование отчёта).
- [x] UI-тесты ключевых экранов (Compose testing).
- [x] Ручное регрессионное прохождение всех сценариев из `draft.md`.
- [x] Полировка UI (Material 3, тёмная тема, edge cases пустых состояний).

**DoD:** все критичные баги закрыты, чек-лист регрессии пройден полностью.

## Milestone 9 — Релиз v1.0 (sideload) (Неделя 11)

- [x] Сборка релизного APK (подписанного) с версией по правилам `plan.md` §3.9, фиксация процедуры обновления вручную с сохранением БД.
- [x] Краткая инструкция по установке/обновлению для родителя (отдельный README).
- [x] Установка на целевое устройство, финальная приёмка.

**DoD:** приложение установлено на устройство ребёнка и работает в реальных условиях ≥7 дней без вмешательства разработчика; имя установленного APK и версия в UI совпадают.

## После MVP (бэклог, не оценивается по срокам)

- Принудительная блокировка приложений (Device Owner/MDM) вместо только оповещения.
- Мульти-профиль (несколько детей на одном или разных устройствах, единый email-отчёт).
- Облачный бэкап/синхронизация статистики.
- Более надёжная доставка отчётов через email API (SendGrid/Mailgun) вместо прямого SMTP.
- Троттлинг/лимит попыток ввода пароля приватного раздела.
- Автообновление вне Google Play (собственный update-checker).
- Актуализация под новые версии Android по мере выхода.

## Легенда

- Недели — условные, при part-time занятости множитель уточняется по факту.
- Каждый Milestone имеет явный DoD — переход к следующему этапу возможен только после его выполнения.
