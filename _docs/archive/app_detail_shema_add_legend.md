# Экран "Детали приложения" — добавление легенды (десятки минут) к часовой диаграмме


## 1. Текущее состояние

Вопреки формулировке в `_docs/app_detail_shema_v2.md` ("план, код не менялся"), раскладка v2 **уже
реализована** в `AppUsageHourlyChart` (`AppDetailScreen.kt:208-296`): 16 горизонтальных строк (часы
06..21), подпись часа слева от каждой строки, бар растёт слева направо, поверх дорожки — 5 вертикальных
линий сетки (`gridLines = 6`, линии на долях `i/6` при `i = 1..5`).

Важный факт, который делает задачу простой: `gridLines = 6` уже делит диапазон 0–60 минут на 6 равных
отрезков по **10 минут** каждый. То есть сетка сейчас *и так* стоит ровно на десятках минут (10, 20, 30,
40, 50) — просто без подписей. Новых вычислений/делений не требуется, нужно только подписать существующие
позиции числами и добавить крайние точки 0 и 60.

## 2. Проблема (со слов пользователя)

Не очевидно, сколько минут использовалось приложение в конкретный час: сетка есть, но что означает
"1-я линия слева", "2-я линия" и т.д. — нужно считать деления или помнить шаг заранее.

## 3. Задача

Добавить **одну** легенду-шкалу над всеми 16 строками (в верхней горизонтальной плоскости диаграммы, не
повторять на каждой строке) с подписями по десяткам минут: `0  10  20  30  40  50  60`, выровненную по той
же горизонтальной оси, что и бары/сетка, чтобы можно было прочитать длину конкретного бара напрямую как
число минут.

## 5. Реализация: структура легенды

Легенда — это ещё один `Row`, который вставляется **один раз**, над `Column` со строками часов (перед
циклом `buckets.forEach`), и должен иметь **точно такой же левый отступ**, как строка часа, чтобы числа
оказались над той же дорожкой бара, а не "поехали" относительно сетки:

```
Row {
    Spacer(width = 28.dp)   // ровно как ширина колонки подписи часа в строке данных
    Spacer(width = 8.dp)    // ровно как Spacer между подписью часа и дорожкой бара
    Box(weight = 1f) {      // сама шкала — той же ширины, что и дорожка бара/сетка
        // 7 подписей: 0, 10, 20, 30, 40, 50, 60
    }
}
```

Т.е. это "призрак" одной строки данных, где вместо подписи часа и бара — заголовок шкалы.

### 5.1 Как разместить 7 подписей внутри `Box(weight = 1f)`

Рекомендуемый вариант — **`Row(horizontalArrangement = Arrangement.SpaceBetween)`** с 7 `Text`
("0","10","20","30","40","50","60") как прямых детей:

- `SpaceBetween` сам прижимает первый элемент к левому краю контейнера, последний — к правому, а
  оставшиеся 5 распределяет равномерно между ними — то есть ровно в тех же долях `i/6`, что и текущие
  линии сетки (`i = 0..6`). Дополнительная арифметика не нужна.
- Не требует ручного вычисления `dp`-смещений и не зависит от фактической ширины дорожки (она разная на
  разных экранах/ориентациях) — `SpaceBetween` работает в терминах уже готового `weight(1f)` контейнера.
- Мелкая неточность: т.к. ширина текста "0" и "60" не равна нулю, визуальный центр крайних подписей будет
  чуть смещён внутрь от самого края дорожки (на пол-ширины текста). Для легенды-ориентира (не научного
  графика) это несущественно; при желании можно скорректировать `textAlign`/паддинги на этапе реализации.
- Стиль текста — тот же `MaterialTheme.typography.labelMedium` /
  `colorScheme.onSurfaceVariant`(возможно на ступень мельче/бледнее, т.к. это вспомогательная ось, а не
  основная подпись), можно `labelSmall`, чтобы визуально не спорить с подписями часов слева.

### 5.2 Где вставить в дереве composable

```
Column (surfaceContainerLow, shapes.small) {
    Row { Spacer(28dp); Spacer(8dp); Box(weight=1f) { легенда 0..60 } }   // НОВОЕ, один раз
    HorizontalDivider или Spacer(4dp)  // опционально, отделить шкалу от строк
    buckets.forEach { bucket -> Row { ... как сейчас ... } }
}
```

Легенда помещается **внутри** того же `Column` с фоном `surfaceContainerLow`/`shapes.small`, что и строки —
чтобы визуально выглядела частью одной карточки диаграммы, а не отдельным блоком текста над ней.

## 6. Побочный нюанс существующего кода — стоит ли трогать

Текущие вертикальные линии сетки в строках данных (`AppDetailScreen.kt:262-274`) позиционируются так:

```kotlin
val xFraction = i.toFloat() / gridLines
Box(
    modifier = Modifier
        .fillMaxHeight()
        .width(0.5.dp)
        .offset(x = (xFraction * 100f).coerceIn(0f, 99f).dp)
        ...
)
```

Это переводит долю `xFraction` (0..1) напрямую в **dp** (`xFraction * 100f`), что верно только если
дорожка бара имеет ширину ровно 100dp. На реальном экране дорожка (`weight(1f)` в `Row`) почти всегда
шире — то есть сегодняшняя сетка **уже не совпадает** с реальными долями 10/20/30/40/50 минут, линии
съезжают влево от своих истинных позиций (чем шире экран — тем заметнее).

**Это существующий баг вне рамок исходной задачи**, но он напрямую влияет на пользу новой легенды: если
подписать шкалу правильно (`SpaceBetween`, см. §5.1), а линии сетки под барами останутся смещены
из-за бага с `offset`, легенда и сетка **разъедутся** между собой — пользователь увидит подпись "20" не
над той линией, которая на самом деле означает 20 минут.

**Рекомендация:** в рамках этой же задачи заодно поправить сетку в строках данных на тот же приём
`fillMaxWidth(fraction)` + `Alignment.CenterEnd`, что и предлагалось изначально в
`_docs/app_detail_shema_v2.md §4.1`, но не было применено при реализации:

```kotlin
for (i in 1 until gridLines) {
    Box(
        modifier = Modifier
            .fillMaxWidth(i.toFloat() / gridLines)
            .fillMaxHeight(),
        contentAlignment = Alignment.CenterEnd
    ) {
        Box(
            modifier = Modifier
                .fillMaxHeight()
                .width(0.5.dp)
                .background(MaterialTheme.colorScheme.outlineVariant.copy(alpha = 0.3f))
        )
    }
}
```

Это даёт те же самые доли `i/6`, что и `SpaceBetween` в легенде (§5.1), — сетка и подписи будут
гарантированно на одной оси на любом экране. Без этого исправления легенда всё равно решает исходную
проблему пользователя ("сколько минут в баре") приблизительно на глаз, но не будет пиксель-в-пиксель
совпадать с текущей (слегка смещённой) сеткой — стоит явно спросить пользователя, входит ли это
исправление в объём, либо просто зафиксировать в чек-листе как рекомендованное попутное исправление.
